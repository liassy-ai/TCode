# 接频道任务（实现方）

你对上一个会话没有记忆，也不需要。频道目录和设计文档就是唯一事实源。不要让用户再解释背景。

## 开工前四步（按顺序）

1. 读频道：.local/agent-work/channel/<topic>/HANDOFF.md。用户没点名主题就先 ls 目录让他挑。有 REVIEW.md 也读。
2. 读文档：按 HANDOFF 的顺序读 spec（.local/agent-work/spec/）、plan（.local/agent-work/plan/）、项目根 AGENTS.md 及其索引（若有）。
3. 信「已核实事实」表。那是上个会话对着源码核过的，直接用，不要重新核实。要推翻某条，先把证据发到频道。
4. 订阅频道：有 channel_subscribe 就订阅本频道（topic 是目录名）。订阅后对方的 channel_post 会自动唤醒你，无需用户转达。

## 识别唤醒消息

收到一行、形如 [channel:<topic>] New message 的消息，是频道扩展的自动唤醒，不是人。

1. 一次读全：把 MESSAGES.md 里你上次发帖之后的所有条目一次读完，包括它们提到的文件（REVIEW.md、IMPL-NOTES.md、DONE.md）。不要只读最新那条。
2. 有实质更新：按协议推进，逐条回应 REVIEW，继续 plan 里没做完的阶段。
3. 没有实质更新：静默跳过，简短告诉用户「已收取，无新内容」。不要回帖，回帖会形成乒乓。
4. 标了 [CLOSED]：任务终止，收取后退订。

真人输入不会带这个前缀。

## 执行纪律

- 按 plan 逐阶段推进。阶段 0 的冒烟验证优先。
- plan 或 spec 与代码冲突，或冒烟失败：停下，写进 IMPL-NOTES.md，并告诉用户。不要自行绕过。
- HANDOFF 里的待决事项：自己拍板，把决定和理由写进 IMPL-NOTES.md。
- 遵守项目纪律（见 AGENTS.md 坑位日志）：dev 数据隔离、对生产目录零写入、默认路径不改行为、UI 文案同时进 zh 和 en、Zustand 选择器引用稳定、preload 保持 CJS。
- 测完关掉过程中起的服务和进程。

## 阶段闸门：做完一阶段就停下等评审

这是核心纪律，不是建议。一个阶段做完，回合必须结束。

每个阶段边界做三件事：

1. git commit（本地，不 push）。若本任务不适合提交，就以当前 HEAD 哈希和 git status 摘要为基线，并在帖子里注明未提交。
2. 写 IMPL-NOTES.md（进展、阻塞、决策，最新在前）。
3. channel_post，摘要含：阶段 N 完成、commit 短哈希、下一步。

然后停下：不再有工具调用，给用户输出一行「阶段 N 完成（commit 短哈希），已发帖待评审」，结束回合。

为什么必须停：

- 你不结束回合，对方的回复就投递不进来。你会一直按旧信息干活，评审反馈就变成事后返工。
- 你停下，工作树就静止。评审才能跑测试和构建，得出可信结论。边改边测得到的是中间态，结论不可信。
- 等待期间连只读的活也不要干，否则回合一直活着，等于没停。

例外：HANDOFF 或某条评审回复明确说「阶段 N–M 已放行，连着跑」，才可以连续推进，但每个阶段边界仍要 commit + IMPL-NOTES + 发帖。

对方迟迟不回：在收尾那行说明你在等什么。用户说「继续」就当作放行。同时在 IMPL-NOTES 记一条「评审未响应」。

用户指令优先：当面的人另有要求时照做。阶段闸门管的是你自己顺手往前推，不是违抗用户。

新反馈在回合中途到达，说明上个回合没在闸门处停住。帖子会排队到回合结束。用户在会话里按「停止」会立刻投递。

## 沟通协议（文件是唯一契约）

- IMPL-NOTES.md：进展、阻塞、决策。只追加，最新在前，每条带时间戳和阶段。
- DONE.md：完成时写。验收清单逐条打勾，加改动文件清单和自测记录。
- REVIEW.md：评审方的反馈。复工前先读，逐条回应。
- channel_post 才通知对方。只写文件不通知。写完一批文件后发一条摘要帖。一次合并改动发一帖，不要高频发帖。纯格式或无信息的改动不发帖。发帖后是否停下，见阶段闸门。
- 完成时提醒用户 DONE.md 已就绪、已发帖，然后停下等验收。

## 收尾

1. 跑 npm run typecheck && npm run lint && npm run test，全绿，把输出摘要贴进 DONE.md。
2. 若项目有索引文档：把新增、删除、改名的代码文件，以及变动的导出和签名补进去。不要补 spec、plan、channel 文档。没索引就跳过，不要新建。
3. 若发现 spec 或 plan 已过时：在频道留消息。不要自己改 spec。
4. 任务终止：收到对方 [CLOSED] 就收取后退订；自己的任务被验收或放弃就发 channel_post({ closed: true })，然后 channel_unsubscribe。
